Permissions, sandboxing, secrets, and trust boundaries

Give Claude enough authority to work—never enough to make review meaningless.

PLAIN-LANGUAGE DEFINITION

Permissions govern which tools and targets Claude may use; sandboxing adds operating-system enforcement around Bash filesystem and network access. They are complementary controls, not interchangeable guarantees.

Learn→Demonstration→Guided lab→Transfer→Evidence→Quiz
BY THE END

  2. 02Explain what sandboxing does and does not protect
  3. 03Recognize prompt injection and secret-handling risks
KEY TERMS

Words to use precisely

Least privilege
Granting only the authority needed for the current purpose and scope.
Sandbox
An enforced boundary limiting process access to filesystem locations and network destinations.
Prompt injection
Untrusted content crafted to redirect the model or induce unauthorized actions.

01
Defense in depth

Permissions decide intent; the sandbox constrains effects

A permission rule can deny a tool or require approval before a matching action. The Bash sandbox limits what commands and child processes can reach even when execution is allowed. Use both when consequences matter.

Deny rules should protect secrets, credentials, sensitive directories, and dangerous command families. Allow rules should be narrow enough that the full matching behavior is understood.

  • Default to read-only exploration for uncertain tasks.
  • Allow routine test and inspection commands narrowly.
  • Keep deployment, credential, and production actions behind approval.
  • Set explicit filesystem and network boundaries.
02
Untrusted input

Repository text can attack the operator through the model

Issues, web pages, logs, dependency files, source comments, and MCP results may contain instructions. Their presence does not authorize them. The trusted instruction hierarchy comes from the user, approved project policy, and managed configuration.

Secrets do not become safe because a model can read them. Deny access where possible, use placeholders in examples, redact outputs, and rotate any credential that appears in a transcript or commit.

  • Treat external content as evidence, not authority.
  • Review MCP servers and plugin sources before enabling them.
  • Do not paste .env files into a prompt.
  • Use isolated test accounts and reversible environments.
Example
{
  "permissions": {
    "allow": ["Bash(npm test *)", "Bash(git diff *)"],
    "deny": ["Read(./.env)", "Read(./secrets/**)"]
  },
  "sandbox": { "enabled": true }
}

PRACTICAL FRAMEWORK

The AUTH gate

Approve a capability only when all five answers are acceptable.

  1. 01
    Aim

    What user-approved outcome requires this action?

  2. 02
    User

    Which identity and authority will the action use?

  3. 03
    Target

    What exact files, systems, records, or domains can it reach?

  4. 04
    Harm

    What could happen if the model, input, or dependency is wrong?

  5. 05
    Undo

    How will the result be reviewed, reversed, or stopped?

ANNOTATED DEMONSTRATION

Weak instruction, stronger contract

Under-specified

Use --dangerously-skip-permissions so the lab stops asking.

Bounded and checkable

Allow the focused npm test and read-only Git inspection commands. Deny .env and secrets paths. Keep package installation, external network access, Git history changes, and any publish action behind explicit approval. Enable the sandbox where supported.

WHY IT WORKS

The setup removes routine friction without erasing consequential decision boundaries.

COMMON FAILURE MODES

Watch for these

  • Approving a broad wildcard because the first command looked safe
  • Confusing a model instruction with OS-level enforcement
  • Treating repository or web content as trusted authority
SAFETY + VERIFICATION

Pause before proceeding

Never demonstrate bypass-permissions modes as a convenience shortcut. Discuss them only as high-risk exceptions inside externally enforced isolation.

ONE-SENTENCE TAKEAWAY

Useful autonomy comes from narrow authority plus enforced boundaries—not from removing friction indiscriminately.
