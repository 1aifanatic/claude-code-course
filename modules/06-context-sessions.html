Control context, sessions, cost, and compaction

Treat attention as a finite engineering resource and sessions as disposable workspaces.

PLAIN-LANGUAGE DEFINITION

Context is everything currently available to the model—system instructions, memory, conversation, file contents, tool output, skill bodies, and tool definitions—within a finite window.

Learn→Demonstration→Guided lab→Transfer→Evidence→Quiz
BY THE END

You will be able to—

  1. 01Inspect what consumes session context
  2. 02Choose between continue, compact, clear, and a new session
  3. 03Keep durable instructions out of fragile conversation history
KEY TERMS

Words to use precisely

Compaction
Summarizing older conversation and tool history to free context space.
Context pollution
Irrelevant, stale, or conflicting material that reduces attention available for the current task.
Session
A resumable conversation and its accumulated context around a working directory.
Open the complete glossary →
01
Attention

More context is not automatically better context

Large command output, broad file reads, repeated failed approaches, oversized instructions, and unused tool definitions all consume attention. The cost is not only tokens; it is reduced adherence and greater chance of mixing assumptions.

Use /context to inspect the actual budget. Ask whether an item must remain always-on, can load on demand as a skill, or belongs in a separate subagent context.

  • Keep startup instructions concise.
  • Write large logs to files and summarize the relevant slice.
  • Use focused searches instead of dumping directories.
  • Delegate noisy research when only its conclusion matters.
02
Session strategy

Choose the cleanest state that preserves the needed decisions

Continue when the task and assumptions remain coherent. Compact when the work is still one task but the history is large. Clear or start fresh between unrelated tasks or after repeated failed approaches.

Before clearing, write durable decisions to SPEC.md, an issue, or another artifact. Conversation is a convenient workspace, not the authoritative project record.

  • /context diagnoses pressure.
  • /compact preserves a focused summary.
  • /clear removes unrelated history.
  • --continue and --resume return to existing work when it is still the right context.
Example
/context
/compact focus on accepted requirements and verification evidence
/clear
claude --continue

PRACTICAL FRAMEWORK

The context placement ladder

Put information in the narrowest layer that reliably needs it.

  1. 01
    Conversation

    One task, temporary reasoning, current feedback.

  2. 02
    Artifact

    Approved spec, plan, decision, or evidence that must survive sessions.

  3. 03
    Skill

    On-demand procedure or reference used for a class of tasks.

  4. 04
    CLAUDE.md or rule

    Concise instruction needed automatically in the relevant scope.

  5. 05
    Subagent

    Noisy side work whose details should not occupy the main context.

ANNOTATED DEMONSTRATION

Weak instruction, stronger contract

Under-specified

Keep correcting Claude in the same 200-message debugging session.

Bounded and checkable

Export the confirmed reproduction, retired hypotheses, current diff, and next experiment to DEBUG.md. Start a clean session with that artifact, the focused test, and the current repository state.

WHY IT WORKS

The useful knowledge survives while accumulated dead ends no longer compete for attention.

COMMON FAILURE MODES

Watch for these

  • Putting every instruction in CLAUDE.md
  • Continuing unrelated tasks in the same session
  • Using compaction as a substitute for writing durable decisions
SAFETY + VERIFICATION

Pause before proceeding

A context audit may reveal secrets or sensitive file names. Record categories and decisions, not confidential values.

ONE-SENTENCE TAKEAWAY

Context quality improves when durable knowledge, on-demand guidance, and disposable exploration live in different places.
