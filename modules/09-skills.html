Build reusable skills

Turn a repeatedly useful procedure into on-demand, testable project knowledge.

PLAIN-LANGUAGE DEFINITION

A Claude Code skill is a directory whose SKILL.md provides reusable instructions, knowledge, or workflow guidance that loads when invoked or judged relevant.

Learn→Demonstration→Guided lab→Transfer→Evidence→Quiz
BY THE END

You will be able to—

  1. 01Recognize when a workflow deserves a skill
  2. 02Author focused frontmatter and instructions
  3. 03Test skill triggering, behavior, and failure cases
KEY TERMS

Words to use precisely

SKILL.md
The required Markdown entry point containing frontmatter and the skill instructions.
Progressive disclosure
Keeping the entry instructions focused while placing detailed references, examples, or scripts in supporting files.
Invocation control
Configuration that determines whether a skill may be selected automatically or only invoked explicitly.

01
Selection

A skill solves repeated context—not every preference

Create a skill when a procedure or reference is useful across multiple tasks but does not deserve always-on context. Examples include reviewing database migrations, preparing releases, diagnosing flaky tests, or formatting a team-specific architecture decision.

Keep the description about when to use the skill, not a full summary of what it contains. A clear trigger helps Claude select it; explicit invocation control is appropriate for consequential actions.

  • One coherent job per skill.
  • Put critical instructions near the top.
  • Link only the references needed for the task.
  • Use scripts for deterministic validation or mechanical work.
02
Evaluation

A skill is not reusable until realistic cases expose its limits

Test obvious matches, paraphrased matches, non-matches, missing prerequisites, hostile input, and partial failure. Inspect whether the skill loads, follows the intended sequence, stays within authority, and produces the required artifact.

Revise the instructions from observed failures. If a rule must run every time regardless of model judgment, move it to a hook rather than repeating stronger prose.

  • Test automatic and explicit invocation separately.
  • Include at least one case that must not trigger.
  • Check behavior after compaction for long-running workflows.
  • Version reference material alongside the skill.
Example
---
name: incident-review
description: Review an incident change for domain invariants and verification evidence. Use after changes to incident behavior.
---

Read references/review-checklist.md. Inspect the diff and tests. Report blockers before suggestions.

PRACTICAL FRAMEWORK

The SKILL contract

A trustworthy skill makes six decisions explicit.

  1. 01
    Signal

    Which requests should activate it?

  2. 02
    Knowledge

    Which on-demand facts or references does it add?

  3. 03
    Instructions

    What sequence and boundaries must be followed?

  4. 04
    Limits

    What must it refuse, escalate, or leave to the user?

  5. 05
    Learning test

    Which cases demonstrate correct trigger and behavior?

ANNOTATED DEMONSTRATION

Weak instruction, stronger contract

Under-specified

A skill named helpful-coder that says to write excellent code.

Bounded and checkable

An incident-review skill triggered after changes to incident domain behavior. It loads the invariant checklist, inspects the diff and focused tests, blocks on authorization or state-machine regressions, and emits a fixed review template. It never edits or approves the change.

WHY IT WORKS

The strong skill has a specific trigger, unique knowledge, bounded authority, and testable output.

TRY IT IN CLAUDE CODE

A reusable starting request

Adapt bracketed material to approved project information. Review proposed actions before granting authority.

Help me design a project skill for [repeated job]. First confirm it belongs in a skill rather than CLAUDE.md, a rule, subagent, or hook. Define trigger, inputs, outputs, procedure, references, authority limits, failure behavior, and six test cases including two non-matches. Then scaffold the skill for review.

GUIDED RELAYBOARD LAB

Build the incident-review skill

25–35 min

Scenario

Create a read-only reviewer that applies RelayBoard’s domain invariants to a proposed change.

Useful command
/incident-review

Work sequence

  1. Create .claude/skills/incident-review/SKILL.md.
  2. Move the detailed invariant checklist into references/domain-invariants.md.
  3. Make the output distinguish blockers, evidence gaps, and suggestions.
  4. Run six cases: direct match, paraphrase, unrelated request, missing diff, unsafe request, and a real incident change.

Record this checkpoint when the skill triggers for both intended phrasings, avoids the unrelated task, and reports a deliberate invariant violation as a blocker.

COMMON FAILURE MODES

Watch for these

  • Using a skill for instructions needed in every session
  • Writing an overly broad description that triggers constantly
  • Testing only the happy path with the author’s exact wording
SAFETY + VERIFICATION

Pause before proceeding

Skills can carry action-oriented instructions. Require explicit invocation for destructive, external, or expensive workflows and keep credentials out of skill files.

ONE-SENTENCE TAKEAWAY

A useful skill is an on-demand contract with a clear trigger, bounded procedure, and evidence from realistic tests.
